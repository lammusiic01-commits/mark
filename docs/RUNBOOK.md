## 0. Что вы скачали

Архив `mark-1.0.0.zip` — полный исходный код проекта:

```
packages/shared      типы, схемы, каталоги сервисов/платформ/регионов/бенчмарков
apps/server          API-сервер: аудит, GEO, рынок, BotShield, гипотезы, планировщик, отчёты
apps/web             интерфейс: Vue 3 + Vite + ECharts (12 разделов)
apps/desktop         MARK Desktop: окна входа в сервисы (Electron)
scripts              запуск dev-окружения, сборка ZIP
Dockerfile, docker-compose.yml   запуск на сервере в контейнере
docs/RUNBOOK.md      этот файл
README.md            описание проекта и API
```

Внутри архива **нет** `node_modules`, базы данных и секретов — их создаёт первый запуск.

## 1. Требования

| Что | Минимум | Откуда |
| --- | --- | --- |
| Node.js | **20.10+** (лучше 22 LTS) | https://nodejs.org — LTS-установщик |
| npm | 10+ (идёт с Node) | — |
| Свободный порт | 8787 (можно поменять) | — |
| ОС | Windows 10+, macOS 12+, Linux | — |

Проверка после установки Node:

```bash
node -v      # должно быть v20.10.0 или выше
npm -v
```

Если на сервере нет прав root — ничего страшного, MARK работает от обычного пользователя
и хранит данные в своей папке.

## 2. Способ A: локальный запуск за 3 команды

```bash
unzip mark-1.0.0.zip
cd mark-1.0.0          # имя папки — как назовёте при распаковке
npm install            # 1–2 минуты: 250 пакетов
npm run build          # 15 секунд: сервер (esbuild) + интерфейс (vite)
npm start              # запуск
```

В консоли появится:

```
MARK 1.0.0 запущен за 97 мс
API: http://localhost:8787/api/meta
Данные: /путь/к/папке/.data
Демо-режим: выключен · Исходящая сеть: разрешена
```

Откройте **http://localhost:8787** — интерфейс готов к работе.
Остановить: `Ctrl + C` в консоли.

Сменить порт / папку данных:

```bash
MARK_PORT=9000 npm start
node apps/server/dist/server.mjs --port 9000 --data-dir ./data --serve-web
```

> **Windows:** команды те же, но `MARK_PORT=9000 npm start` пишите как
> `set MARK_PORT=9000 && npm start` (cmd) или `$env:MARK_PORT=9000; npm start` (PowerShell).

## 3. Способ B: режим разработки

Нужен, если планируете править код: сервер сам перезапускается, интерфейс обновляется на лету.

```bash
npm run dev
```

- интерфейс: http://localhost:5173
- API: http://localhost:8787 (запросы проксируются автоматически)

Если порт 8787 занят — задайте свой и укажите фронтенду, куда проксировать:

```bash
MARK_PORT=8801 npm run dev
```

## 4. Способ C: Docker (сервер, VPS)

Самый простой вариант для круглосуточной работы. Нужен Docker с плагином compose.

```bash
unzip mark-1.0.0.zip && cd mark-1.0.0
mkdir -p data && sudo chown 1000:1000 data   # папка данных для пользователя контейнера
docker compose up -d --build                 # сборка и запуск в фоне
docker compose logs -f mark                  # смотреть логи
```

Откройте **http://IP-сервера:8787**.

Что важно знать:

- данные (база, отчёты, ключ шифрования) лежат в `./data` рядом с `docker-compose.yml`
  и переживают пересборку контейнера;
- порт меняется в `docker-compose.yml` (`"9000:8787"`), снаружи будет 9000;
- переменные окружения задаются там же: `MARK_DEMO_MODE`, `MARK_ALLOW_OUTBOUND`, `MARK_DRY_RUN`;
- обновление: распаковать новую версию кода в ту же папку (папку `data` не трогать) и выполнить
  `docker compose up -d --build`.

Проверка здоровья:

```bash
curl http://localhost:8787/api/health
```

## 5. Способ D: MARK Desktop — окна входа в сервисы

Нужен, когда сервис нельзя подключить токеном и требуется войти в аккаунт **внутри приложения**
(Яндекс.Директ, Метрика, Вебмастер, Google Ads/Analytics/GSC, Tilda, WordPress, Cloudflare и другие).

```bash
# сервер должен быть уже запущен (см. способы A–C)
npm run desktop:install     # один раз: скачивает Electron
npm run desktop:start
```

В открывшемся окне «MARK Desktop»:

1. сверху видно «API: доступен» — значит связь с сервером есть (если нет, нажмите «Проверить API»
   или «Запустить сервер» — приложение поднимет локальный сервер само);
2. нажмите **Открыть MARK** — откроется интерфейс в отдельном окне;
3. в интерфейсе: **Подключения** → нужный сервис → способ авторизации «Окно в приложении» → **Открыть**;
4. появится окно входа сервиса — войдите как обычно (пароль, СМС, капча остаются у вас);
5. вернитесь в «MARK Desktop»: видно, сколько cookies найдено →
   **Сохранить сессию** (или включите галочку «Автосохранение» — cookies уйдут в MARK сразу);
6. в MARK подключение станет действующим, и сервис будет работать под вашей сессией.

Сборка установщика для переноса на другой компьютер:

```bash
npm run desktop:dist          # Windows: NSIS + ZIP
npm --prefix apps/desktop run dist:mac
npm --prefix apps/desktop run dist:linux
```

## 6. Автозапуск как служба

Чтобы «бот» работал без открытой консоли.

### Linux (systemd)

```ini
# /etc/systemd/system/mark.service
[Unit]
Description=MARK — SEO/GEO, BotShield, реклама
After=network-online.target

[Service]
Type=simple
User=mark
WorkingDirectory=/opt/mark
Environment=NODE_ENV=production
Environment=MARK_PORT=8787
Environment=MARK_DATA_DIR=/opt/mark/.data
ExecStart=/usr/bin/node /opt/mark/apps/server/dist/server.mjs --serve-web
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now mark
sudo systemctl status mark
sudo journalctl -u mark -f      # логи
```

### PM2 (любая ОС)

```bash
npm i -g pm2
pm2 start apps/server/dist/server.mjs --name mark -- --serve-web
pm2 save
pm2 startup                 # команду из вывода выполнить один раз
pm2 logs mark
```

### Windows (без службы)

Создайте `start-mark.cmd` рядом с проектом:

```bat
@echo off
cd /d %~dp0
set MARK_PORT=8787
node apps\server\dist\server.mjs --serve-web
```

и добавьте его в «Планировщик заданий» → Задача при входе в систему.
Для настоящей службы удобнее `nssm install MARK "C:\Program Files\nodejs\node.exe" "C:\mark\apps\server\dist\server.mjs --serve-web"`.

## 7. Первый вход и демо-данные

При первом старте MARK сам создаёт демонстрационные данные: 3 клиента, 3 сайта
(Tilda-лендинг, WordPress, Next.js на Vercel), 6 кампаний, 12+ гипотез, 4 правила автооптимизации
и тестовый лог nginx для BotShield. Это удобно, чтобы осмотреть интерфейс.

Демо-сайты не существуют в интернете, поэтому аудит по ним выполняется на демонстрационном слепке
страниц и отмечает это замечанием «Сайт недоступен: анализ по демонстрационному слепку» —
вы видите, какие проблемы и правки MARK умеет находить, не получая ложных выводов.

Когда готовы работать по-настоящему:

1. **Настройки** → «Клиенты агентства» → удалите демо-клиентов;
2. **Сайты** → удалите демо-сайты;
3. при желании полностью очистить базу: остановите сервер, удалите папку `.data`, запустите снова
   и выполните `npm run seed` — MARK создаст только «пустой» набор.

## 8. Подключение сервисов

Раздел **Подключения** — мастер из трёх шагов.

**Шаг 1. Выбор сервиса.** В каталоге 23 сервиса: Яндекс.Директ, Метрика, Вебмастер, Бизнес, GPT;
Google Ads, Analytics, Search Console, Business Profile; VK Реклама и Метрика; Tilda, WordPress,
Vercel, Netlify, GitHub, Webflow, Cloudflare, FTP/SFTP, Telegram, SMTP, OpenAI, IndexNow.
Поиск — по названию, назначению и возможностям.

**Шаг 2. Способ авторизации.** У каждого сервиса показано, что он даёт и сколько автоматизации
(полная / частичная / только подготовка файлов):

| Способ | Когда выбирать | Что делать |
| --- | --- | --- |
| API-токен | сервис даёт токен в настройках аккаунта | вставить токен, MARK проверит его живым запросом |
| OAuth | у сервиса есть кнопка «Разрешить» | нажать «Подключить», подтвердить доступ в браузере |
| Окно в приложении | API ограничен или требует браузерной сессии | запустить MARK Desktop (способ D выше) |
| Ручной импорт cookies | вход в окне недоступен | DevTools → Network → любой запрос → скопировать Cookie |

**Шаг 3. Проверка и сохранение.** MARK прогоняет настоящую проверку по шагам (видно по каждому пункту:
что именно проверено, что ответил сервис) и сохраняет подключение. Секреты шифруются
(AES-256-GCM, ключ в `.data/vault.key`), в интерфейс возвращается только маска.

Если проверка не прошла, в карточке подключения написано, что именно ответил сервис —
обычно это истёкший токен или не выданные права (scope).

## 9. Подключение сайта клиента и автонастройка SEO/GEO

Это главный сценарий: MARK сам настраивает SEO и GEO на сайте клиента, независимо от платформы.

**Шаг 1. Добавить сайт.** Раздел **Сайты** → «Добавить сайт» → адрес и название.
MARK сразу определяет платформу (Tilda, WordPress, Vercel, Netlify, Next.js, Webflow, Wix, Shopify,
Ghost, Bitrix, MODX, статика), показывает уверенность и доказательства, предлагает коннекторы.

**Шаг 2. Подключить доступ к сайту** — что доступно для вашей платформы:

| Платформа | Что подключить в «Подключениях» |
| --- | --- |
| сайт в Git (Vercel, Netlify, GitHub Pages) | GitHub (токен с правом `contents:write`) |
| WordPress | WordPress (URL сайта + логин + Application Password) |
| Tilda | Tilda (API-ключ аккаунта и проект) |
| обычный хостинг | FTP или SFTP (хост, логин, пароль) |
| Cloudflare-зона | Cloudflare (токен с правом на DNS/правила) |
| конструктор без API | ничего: MARK подготовит пакет файлов и инструкцию |

**Шаг 3. Аудит.** В карточке сайта нажмите **Аудит**. Видно живой прогресс: краулинг, проверки,
скорость. В итоге — балл 0–100, оценка A–F и список замечаний: у каждого есть доказательство,
рекомендация и признак «исправляется автоматически».

**Шаг 4. Автоисправления.** Нажмите **Автофикс**:

- сначала `Сначала посмотреть файлы` — MARK соберёт готовые файлы (robots.txt, sitemap.xml, llms.txt,
  JSON-LD LocalBusiness и FAQ, meta-обновления, nginx/.htaccess, редиректы) и покажет план;
- затем `Применить` — файлы уйдут через коннектор площадки (коммит в репозиторий, REST WordPress,
  API Tilda, загрузка по FTP). Для платформ без API MARK отдаёт пакет файлов + инструкцию
  «что и куда вставить».

По умолчанию включён безопасный режим: ничего не пишется на сайт, пока вы не нажмёте «Применить».
Переменная `MARK_DRY_RUN=1` запрещает запись полностью — удобно для первых экспериментов.

**Шаг 5. GEO.** Раздел **GEO-анализ**: выберите сайт, ключевые фразы и регионы → «Проанализировать».
MARK покажет спрос по регионам, CPC, приоритеты (high/medium/low) и построит план региональных
страниц (подпапки / поддомены / один сайт): URL, title, description, H1, hreflang, задачи для команды
и готовую разметку LocalBusiness для вставки.

**Шаг 6. Сообщить поисковикам.** Кнопки в карточке сайта: IndexNow (мгновенное уведомление
Яндекса и Bing), переобход в Яндекс.Вебмастере, отправка sitemap в Google Search Console.

**Шаг 7. Отчёт.** Раздел **Отчёты** → «Собрать отчёт» → тип, период, оформление. Через несколько
секунд готов HTML-документ под брендом вашего агентства; скачивается в HTML, CSV и PDF.

## 10. Чтобы «бот» работал сам

После настройки подключений включите расписание — дальше MARK работает без вас.

**Шаг 1. Раздел «Автооптимизация» → «Установить готовые правила».** Появятся 4 правила:

| Правило | Что делает | Расписание |
| --- | --- | --- |
| Снижение ставок при дорогом CPA | находит фразы дороже целевого CPA и понижает ставку | ежедневно, 10:00 |
| Пауза фраз без конверсий | останавливает фразы, которые съедают бюджет без заявок | ежедневно, 11:00 |
| Автоисправления на сайте | применяет исправимые замечания последнего аудита | по расписанию правила |
| Еженедельный отчёт руководству | собирает и отправляет отчёт | понедельник, 09:00 |

Каждое правило можно открыть и изменить: cron-выражение, часовой пояс, порог метрики, процент
изменения ставки, лимит изменений за прогон, уведомления (в приложении, Telegram).

**Шаг 2. Решить, как применять изменения.** В правиле есть галочка «Требовать подтверждение»:

- **включена** — MARK готовит изменения и складывает их в блок «Ждут подтверждения»: вы смотрите
  список «было → стало → причина» и нажимаете «Применить» (безопасно, рекомендуется на старте);
- **выключена** — изменения применяются сразу в рамках лимита из правила.

**Шаг 3. Подключить уведомления.** Telegram: подключите сервис Telegram (токен бота + chat id) —
правила будут присылать отчёты о прогонах в чат. E-mail: подключите SMTP и укажите адрес
в **Настройках** → «E-mail для отчётов по умолчанию».

**Шаг 4. Проверить руками.** У любого правила есть две кнопки: «прогон без применения» (иконка глаза)
и «прогон с применением» (иконка play). Первый раз прогоните без применения — увидите, что именно
сделал бы MARK.

**Шаг 5. Полный цикл одной кнопкой.** Раздел «Автооптимизация» → «Запустить полный цикл»:
аудит → автоисправления → GEO → рынок → гипотезы → отчёт, с живым прогрессом по шагам.
То же самое по API:

```bash
curl -X POST http://localhost:8787/api/quick-run \
  -H 'content-type: application/json' \
  -d '{"clientId":"<id клиента>"}'
```

**Шаг 6. Гипотезы.** Раздел **Гипотезы** → «Сгенерировать из данных» — MARK соберёт гипотезы роста
из последнего аудита, BotShield, GEO и рынка, с ICE-приоритетом и планом A/B-теста.
Запускаете тест кнопкой, вносите результаты — MARK посчитает значимость (z-тест, t-тест Уэлча)
и сам переведёт гипотезу в «подтверждена» или «отклонена».

Итого «бот работает сам», когда включено: правила автооптимизации + правила с подтверждением или без,
уведомления в Telegram/e-mail и служба автозапуска (раздел 6).

## 11. BotShield: где взять логи и как запустить разбор

Раздел **BotShield** → выбрать источник:

| Источник | Что нужно |
| --- | --- |
| Загрузить файл | access.log с сервера (nginx, Apache) или JSON-выгрузка |
| Ссылка на лог | прямой URL файла лога, если он доступен по ссылке |
| Коннектор | подключённый FTP/SFTP-аккаунт: MARK сам заберёт файл журнала |
| Демо-данные | встроенный пример, чтобы посмотреть возможности |

Где взять лог:

- nginx: `/var/log/nginx/access.log` (на хостинге часто доступен по FTP или в панели «Файлы»);
- Apache: `/var/log/apache2/access.log`;
- Cloudflare: Analytics → Logpush (JSON), либо экспорт из панели;
- виртуальный хостинг без доступа к логам: возьмите выгрузку «статистика посещений» в панели
  или выгрузите лог через SFTP у хостинг-провайдера.

Нажмите **Проанализировать**. MARK покажет:

- чистоту трафика в процентах, число запросов, уникальных IP, подозрительных обращений;
- сожжённые гигабайты и **потери в рублях** (считаются по стоимости трафика и цене визита);
- графики трафика по дням и по странам, топ ASN;
- таблицы: классификация (люди, поисковые боты, AI-краулеры, подозрительные, атаки), IP,
  конкретные боты, страницы, рекомендации;
- готовые артефакты защиты: правила nginx, robots.txt, llms.txt, Cloudflare, .htaccess —
  копируются кнопкой и применяются через коннектор (например, в GitHub/FTP) или вручную.

Для проверки одного адреса — `POST /api/bots/classify` с `{ "ip": "...", "userAgent": "..." }`.

## 12. Отчёты клиентам и белая метка

**Раздел «Белая метка».** Укажите название агентства, два цвета, логотип, контакты и подпись,
включите «Скрыть упоминания MARK». Справа — предпросмотр: так документ увидят клиенты.

**Раздел «Отчёты».** «Собрать отчёт» → тип (общий свод, SEO, GEO, BotShield, рынок, кампании,
гипотезы), период, «включать графики», «оформление агентства» и каналы доставки сразу после сборки:

- **в приложении** — открывается в предпросмотре;
- **e-mail** — нужен подключённый SMTP и адреса получателей;
- **Telegram** — нужен бот и chat id.

Экспорт: HTML (открыть в браузере), CSV (данные для таблиц), PDF (Chromium; если его нет —
откроется печатная версия, сохраните «как PDF» средствами браузера).

## 13. Резервные копии и обновление

Всё состояние MARK лежит в одной папке `.data`:

```
.data/mark.sqlite   база: клиенты, сайты, кампании, гипотезы, отчёты
.data/vault.key     ключ шифрования секретов  ← храните отдельно и бережно
.data/reports/      готовые HTML/CSV-отчёты и пакеты правок
.data/sessions/     материалы окон входа
```

**Бэкап:**

```bash
tar -czf mark-backup-$(date +%F).tar.gz .data
```

Достаточно остановить сервер на время копирования либо копировать `.data` целиком — база пишется
с дебаунсом, но безопаснее останавливать.

**Обновление:** распакуйте новую версию кода в отдельную папку, перенесите туда `.data`,
выполните `npm install && npm run build`, перезапустите службу. Папку `.data` между версиями
переносить обязательно — иначе потеряются подключения (ключ шифрования) и история.

**Важно:** файл `.data/vault.key` — единственный ключ к сохранённым секретам. Потеряете его —
подключения придётся создавать заново.

## 14. Доступ из интернета (nginx + HTTPS)

MARK не имеет встроенной авторизации: он рассчитан на локальную сеть агентства. Если открываете
его наружу — закройте хотя бы базовой авторизацией и HTTPS.

```nginx
server {
  listen 443 ssl http2;
  server_name mark.agency.ru;

  ssl_certificate     /etc/letsencrypt/live/mark.agency.ru/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/mark.agency.ru/privkey.pem;

  auth_basic           "MARK";
  auth_basic_user_file /etc/nginx/.htpasswd;   # htpasswd -c /etc/nginx/.htpasswd agent

  location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header Upgrade $http_upgrade;      # WebSocket: живой прогресс
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
    client_max_body_size 64m;                    # загрузка логов BotShield
  }
}
```

WebSocket (`/ws`) обязателен для живого прогресса; если прокси его не пропускает, интерфейс
всё равно работает — просто обновления приходят по опросу.

## 15. Частые проблемы

| Симптом | Причина и решение |
| --- | --- |
| `EADDRINUSE: address already in use 8787` | порт занят: запустите с `--port 8801` или закройте старый процесс (`lsof -i :8787`, Windows: `netstat -ano | findstr 8787`) |
| `npm start` отдаёт JSON вместо интерфейса | фронтенд не собран: выполните `npm run build` |
| `Не найден файл sql-wasm.wasm` | не выполнен `npm install` в корне проекта |
| Белый экран в браузере | откройте консоль (F12): чаще всего это прокси без WebSocket или старый кэш — обновите с `Ctrl+F5` |
| Проверка токена не проходит | истёк токен или не выданы права; в карточке подключения видно ответ сервиса |
| Окно входа не открывается в браузере | это нормально: окна входа работают в MARK Desktop (`npm run desktop:start`) |
| Playwright: «нет графического окружения» | на сервере без GUI используйте MARK Desktop или ручной импорт cookies |
| PDF-отчёт открывается как печатная страница | Chromium недоступен — сохраните PDF из диалога печати |
| Аудит показал «демонстрационный слепок» | сайт не открылся (нет сети, staging под паролем, опечатка в адресе) — исправьте адрес и повторите |
| Внешние запросы не уходят | проверьте `MARK_ALLOW_OUTBOUND` (должно быть `1`) и `MARK_DEMO_MODE` (должно быть `0`) |
| Правило не срабатывает по расписанию | сервер должен быть постоянно запущен (служба, раздел 6); проверьте часовой пояс в правиле |

Проверка состояния системы в любой момент: раздел **Настройки** (окружение, счётчики, диагностика
подключений) или `curl http://localhost:8787/api/system/status`.
