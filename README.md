# MARK — платформа автоматизации SEO/GEO, защиты от ботов и управления рекламой

MARK — это самохостящееся приложение для digital-агентства: оно **само** анализирует сайт клиента,
находит проблемы, готовит и применяет исправления, подбирает регионы для GEO-продвижения, считает
экономику рекламы, чистит трафик от ботов и присылает клиенту готовый отчёт под брендом агентства.

Работает на одной машине (Windows/macOS/Linux), данные и секреты остаются у вас: SQLite-файл в `.data/`,
пароли и токены — в зашифрованном виде (AES-256-GCM).

## Что умеет

**Сайт и SEO (модуль SEO)**
- определяет платформу сайта по адресу: Tilda, WordPress, Vercel, Netlify, Next.js, Webflow, Wix, Shopify, Ghost, Bitrix, MODX, 1С-Битрикс и статику;
- обходит сайт краулером (robots.txt, sitemap, внутренние ссылки, заголовки, картинки, разметка);
- делает аудит по ~40 правилам: техническая часть, индексация, контент, скорость, мобильная версия, ссылки, локальное SEO, готовность к ИИ-поиску;
- считает балл 0–100 и оценку A–F, показывает каждое замечание с доказательством, рекомендацией и флагом «исправляется автоматически»;
- **готовит и применяет исправления сам**: robots.txt, sitemap.xml, llms.txt, meta-теги, canonical, alt у картинок, JSON-LD (LocalBusiness, FAQ), 301-редиректы, заголовки безопасности, nginx/.htaccess;
- отправляет изменения через коннектор площадки (GitHub, FTP/SFTP, WordPress REST, Tilda API, Cloudflare, Vercel) либо выдаёт готовый пакет файлов, если у платформы нет API;
- сообщает поисковикам о новых адресах: IndexNow, переобход в Яндекс.Вебмастере, отправка sitemap в Google Search Console.

**GEO (региональное продвижение)**
- собирает спрос по регионам (Яндекс.Вордстат по `lr`, при отсутствии доступа — встроенные бенчмарки);
- сравнивает CPC региона с Москвой, расставляет приоритеты high/medium/low;
- строит карту региональных страниц (подпапки / поддомены / один сайт), заголовки, hreflang, задачи для команды;
- готовит локальную разметку LocalBusiness с адресом, телефоном и зоной обслуживания.

**Реклама и деньги**
- Market Analyzer: CPC ниши по бенчмаркам против вашего факта, разрыв в %, три сценария бюджета (экономный/сбалансированный/агрессивный) с кликами, конверсиями и CPA;
- кампании: список с метриками, предупреждения (перерасход, дорогой CPA, простой), рекомендации по ставкам с обоснованием;
- применение ставок в Яндекс.Директе по API (без боевого токена — только предпросмотр, изменения не уходят);
- гипотезы роста: генерация из аудита/BotShield/GEO/рынка, ICE-приоритет, план A/B-теста с минимальной выборкой, статистическая оценка результата (z-тест, t-тест Уэлча).

**BotShield — защита от ботов**
- разбирает логи nginx, Apache, JSON и Cloudflare Logpush;
- классифицирует трафик: люди, поисковые боты, AI-краулеры, подозрительные, атаки (SQL-инъекции, перебор паролей, сканеры);
- считает «чистоту трафика», сожжённые гигабайты и потери в рублях;
- выдаёт готовые артефакты: правила nginx, robots.txt, llms.txt, Cloudflare, .htaccess;
- ведёт историю сканов и алерты в дашборде.

**Автооптимизация и отчёты**
- планировщик на cron: снижение ставок при дорогом CPA, пауза фраз без конверсий, добавление минус-слов, автоисправления, недельный отчёт;
- правила с обязательным подтверждением: MARK готовит изменения, вы проверяете и применяете;
- уведомления в приложении и Telegram, доставка отчётов по e-mail (SMTP);
- отчёты под белой меткой: своё название, цвета, логотип, подписи, дисклеймер; экспорт HTML, CSV и PDF (Chromium, с резервом — печать из браузера);
- «полный цикл одной кнопкой»: аудит → автоисправления → GEO → рынок → гипотезы → отчёт, с живым прогрессом по WebSocket.

**Белая метка для агентств**
Клиент не видит MARK: в интерфейсе и отчётах — название, цвета, логотип и контакты агентства.

## Как подключить сервис (включая вход в окне приложения)

Раздел **Подключения** — мастер из трёх шагов: выбрать сервис → выбрать способ авторизации →
проверить и сохранить. Проверка идёт в реальном времени: шаги валидации приходят по WebSocket,
провал виден сразу, токен нигде не показывается (только маска).

Каталог содержит 23 сервиса: Яндекс.Директ, Метрика, Вебмастер, Бизнес, GPT; Google Ads, Analytics,
Search Console, Business Profile; VK Реклама и Метрика; Tilda, WordPress, Vercel, Netlify, GitHub,
Webflow, Cloudflare, FTP/SFTP-хостинг; Telegram, SMTP, OpenAI, IndexNow.

Четыре способа авторизации:

1. **API-токен / OAuth** — для сервисов с открытым API. Кнопка «Подключить» запускает OAuth-поток
   (`/api/oauth/:serviceId/start`) либо принимает токен, который MARK тут же проверяет реальным запросом.
2. **Окно входа в приложении** — там, где API нет или он ограничен. MARK открывает страницу входа
   сервиса **внутри приложения**, вы входите как обычно (пароль, СМС, капча — только у вас),
   приложение забирает cookies и отдаёт их серверу (`POST /api/sessions/:id/cookies`).
   Дальше сервисом управляет MARK — от вашего имени и в рамках вашей сессии.
3. **Браузер на сервере (Playwright)** — тот же сценарий, но окно открывает сервер; нужен графический
   рабочий стол (на сервере без GUI честно сообщит, что режим недоступен).
4. **Ручной импорт cookies** — если вход в окне невозможен: скопируйте заголовок Cookie из DevTools,
   вставьте в MARK, сессия сохранится зашифрованной.

Безопасность: пароли MARK не запрашивает и не хранит — только сессионные cookies, и только чтобы
работать от вашего имени. Cookies шифруются ключом `.data/vault.key`, живут в вашем `.data/`, и их
можно отозвать (кнопка «Удалить подключение» стирает и секрет, и запись).

## Как MARK подключается к сайту на любой платформе

Схема одна и та же, независимо от того, на чём сделан сайт:

1. **Определение платформы** — `POST /api/sites/detect` (плюс ручной выбор, если нужно): HTML,
   заголовки, meta generator, CDN, структура URL. Итог — платформа, уверенность, доказательства
   и список рекомендованных коннекторов.
2. **Аудит** — `POST /api/sites/:id/audit`: краулинг, ~40 проверок, балл, замечания с признаком
   автоисправляемости. Прогресс идёт в канал `audit:<id>`.
3. **Пакет правок** — `POST /api/sites/:id/autofix` в режиме `preview`: MARK собирает готовые файлы
   (robots.txt, sitemap.xml, llms.txt, JSON-LD, meta-обновления, nginx/.htaccess, CSV с правками alt)
   и показывает план применения.
4. **Применение** — тот же маршрут в режиме `apply`: файлы уходят через коннектор площадки.

| Платформа | Как применяются правки |
| --- | --- |
| GitHub / Vercel / Netlify (сайт в репозитории) | коммит файлов в ветку через GitHub API, дальше — автоматический деплой |
| WordPress | REST API: meta-теги, описания, заголовки, разметка |
| Tilda | API проекта: meta-обновления, вставка HTML в head |
| Любой хостинг с FTP/SFTP | загрузка файлов в корень сайта |
| Cloudflare | создание правил и редиректов через API зоны |
| Платформа без API (конструктор, самописная CMS) | MARK отдаёт **пакет файлов и инструкцию** (`.data/reports/patch-<id>`): что и куда вставить, готовые к копированию |
| Нужен вход в панель без токена | окно входа в приложении + cookies (см. выше), далее MARK работает в сессии платформы |

Порядок «сухой прогон» соблюдается всегда: по умолчанию изменения только готовятся
(`MARK_DRY_RUN=1` — вообще никогда не пишет на реальные сайты). Ничего не уходит на сайт клиента
без явного нажатия «Применить».

## Приложение MARK Desktop (Electron)

Настольная оболочка нужна для двух задач: держать интерфейс и открывать окна входа сервисов
внутри приложения (в браузере так нельзя — мешают CORS и sandbox iframe).

```bash
npm run desktop:install
npm run desktop:start
```

Что внутри:

- панель подключений: статус API, запуск локального сервера одной кнопкой, настройка адреса API;
- окно входа сервиса: открывается рядом, вы логинитесь, cookies забираются кнопкой «Сохранить сессию»
  или автоматически (галочка «Автосохранение»);
- журнал: видно, что происходит с сервером и сессиями;
- отдельное окно с интерфейсом MARK (кнопка «Открыть MARK»).

Веб-интерфейс, открытый в MARK Desktop, получает мост `window.mark` и в разделе «Подключения»
показывает кнопки «Открыть» (окно в приложении) и «Забрать cookies». В обычном браузере этих
кнопок нет — там доступны Playwright и ручной импорт.

Сборка установщика: `npm run desktop:dist` (electron-builder, NSIS/ZIP для Windows, DMG для macOS,
AppImage для Linux).

## Telegram-бот и мини-приложение

MARK работает как продукт в телефоне: бот пишет сводки и принимает команды, а приложение внутри Telegram
(`https://ваш-адрес/#/tg`) открывается одной кнопкой — тёмный премиум-интерфейс с тактильным откликом,
оплатой по СБП, онбордингом «где взять каждый ключ» и AI-советником.

**Что видно в приложении:** Сводка · Рост и SEO (аудит, автоисправления, GEO, рынок) · BotShield ·
Кампании и ставки · Гипотезы · Баланс и СБП · Подключения · Отчёты · Настройки.

**Что умеет бот:** `/start`, `/menu`, `/status`, `/sites`, `/audit`, `/geo`, `/market`, `/bots`,
`/hypotheses`, `/report`, `/quick`, `/clients`, `/link`, `/help` и свободный текст (трактуется как аудит).

Быстрый старт:

```bash
# 1. токен у @BotFather → в окружение
export MARK_TELEGRAM_BOT_TOKEN=7712345678:AAH...
export MARK_PUBLIC_URL=https://mark.agency.ru        # HTTPS-адрес сервера (нужен для кнопки приложения)

# 2. работа из России: прокси через Cloudflare Worker
export MARK_TELEGRAM_API_BASE=https://tg-proxy.<аккаунт>.workers.dev

# 3. запуск — в логе появится «Telegram-бот @... запущен»
npm start
```

Полная инструкция — [docs/TELEGRAM.md](docs/TELEGRAM.md): создание бота, код воркера-прокси,
переменные, доступы и роли, частые проблемы. Управление ботом из интерфейса — **Настройки →
«Telegram-бот и приложение»** (статус, тестовое сообщение, перезапуск, приглашение для сотрудников).

## Архитектура

```
packages/shared      типы, zod-схемы, каталоги (сервисы, платформы, регионы, бенчмарки, боты), формулы
apps/server          Express + ws: API, аудит, GEO, рынок, BotShield, гипотезы, планировщик, отчёты
apps/web             Vue 3 + Vite + Pinia + ECharts: 12 разделов интерфейса
apps/desktop         Electron: панель подключений, окно входа сервисов, локальный сервер
scripts              dev-окружение, упаковка ZIP
```

Ключевые решения:

- **Хранилище — sql.js (SQLite в WASM)**: файл `.data/mark.sqlite`, никаких нативных сборок.
  Сущности лежат в таблице `objects` (kind + id + JSON), секреты — в `secrets` (AES-256-GCM),
  события — в `events`, метрики — в `metrics`. Запись с дебаунсом, чтобы не тормозить.
- **Реальное время — WebSocket `/ws`** с каналами `test` (валидация), `login` (окна входа), `run`
  (оркестратор), `report`, `audit`, `scan`, `activity`. Есть резервный SSE `/api/events/stream`.
- **Внешние запросы — один HTTP-клиент** (`http/client.ts`): таймауты, повторы, лимиты размера,
  учёт `MARK_ALLOW_OUTBOUND`.
- **Коннекторы сайта** (`services/site/connectors.ts`): GitHub, FTP, SFTP, WordPress, Tilda,
  Cloudflare, IndexNow, Яндекс.Вебмастер, GSC — каждый умеет `dryRun`.
- **Сервер собирается esbuild в один ESM-файл** `apps/server/dist/server.mjs`; тяжёлые пакеты
  (express, ws, sql.js, playwright-core) остаются внешними.

## Безопасность

- Секреты хранятся зашифрованными (AES-256-GCM), ключ — в `.data/vault.key`; папка `.data/` в `.gitignore`.
- В интерфейс секреты никогда не возвращаются: только маскированные превью.
- Окна входа не перехватывают пароли: страница сервиса грузится в изолированной сессии Electron,
  MARK забирает только cookies этого домена.
- Все изменения на сайте клиента по умолчанию — «сухой прогон»; боевое применение требует нажатия
  «Применить», а переменная `MARK_DRY_RUN=1` запрещает запись полностью.
- `MARK_ALLOW_OUTBOUND=0` полностью отключает исходящие запросы — удобно для аудита из закрытого контура.

## Частые проблемы

| Симптом | Что делать |
| --- | --- |
| `EADDRINUSE` при запуске | порт занят другим процессом: `--port 8801` или закройте старый сервер |
| Порт занят, процесс не находится | `lsof -i :8787` (macOS/Linux), `netstat -ano | findstr 8787` (Windows) |
| Фронтенд не открывается `npm start` | сначала `npm run build` — сервер отдаёт `apps/web/dist` |
| Окно входа не появляется в браузере | так и должно быть: окна входа работают в MARK Desktop (`npm run desktop:start`) |
| Playwright пишет, что нет дисплея | на сервере без GUI используйте MARK Desktop или ручной импорт cookies |
| PDF-отчёт открывается как печатная страница | нет Chromium: сохраните PDF из диалога печати |
| Внешние запросы падают | проверьте `MARK_ALLOW_OUTBOUND` и `MARK_DEMO_MODE`; в демо-режиме MARK работает на бенчмарках |
